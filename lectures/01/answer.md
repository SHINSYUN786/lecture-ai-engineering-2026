## 宿題

- 取り組んだレベル：基礎 / 実装 / 発展（3つとも）
- 使ったモデル：`gemini-3.5-flash-lite`（既定）、発展の比較で `gemini-3.5-flash` も使用

### 基礎：同じ質問を繰り返し、temperature を変えて比べる

`python -m app.ask -t 0.0 -n 3 "LoRAとは何ですか？"` のように、`-t`（temperature）、`-m`（モデル）、
`-n`（繰り返し回数）を指定できるようにした。`generate_content` の `config` 引数に
`types.GenerateContentConfig(temperature=...)` を渡している。

- temperature 0.0 の3回：正式名称（Low-Rank Adaptation）、「付箋を貼るように一部だけ学習する」という比喩、
  メリットとして省リソース・小さいファイル・切り替えやすさ、という骨格は3回とも同じだった。
  ただし文章そのものは3回とも違い、0.0 でも完全には一致しなかった。出力トークンは 553 / 580 / 605。
- temperature 2.0 の3回：同じく骨格は同じで、見出しの構成や例えが入れ替わる程度の違いだった。
  出力トークンは 632 / 486 / 600。0.0 の場合と比べて、内容が崩れるような差は見られなかった。
- 気づき：この質問のような知識の問いでは、temperature を最大にしても事実の内容はほぼ変わらず、
  表現（構成・例え・語尾）だけが変わった。0.0 でも揺れるので、完全に同じ出力は期待できない。

### 実装：会話履歴を保って続けて質問する

`python -m app.ask --chat` で、`client.chats.create` のチャットセッションを使い、
空行か Ctrl-D で終わるまで続けて質問できるようにした。履歴ぶん、ターンが進むほど入力トークンが増える。

- 結果：3ターン続けて質問した。
  1. 「LoRAとは何ですか？」→ 通常の説明（入力 9 / 出力 530）
  2. 「それを一言でまとめて」→ 直前のLoRAの説明を指す「それ」を正しく理解し、一文にまとめた（入力 545 / 出力 30）
  3. 「さっきの最初の質問は何でしたか？」→ 「LoRAとは何ですか？」と、最初の質問を答えた（入力 586 / 出力 15）
- 気づき：履歴が保たれているため、2ターン目以降は質問が短くても文脈が通じた。
  一方で入力トークンは 9 → 545 → 586 と増えた。履歴（前の質問と回答の全文）が毎回入力として送られるためで、
  会話が長くなるほど入力トークンと料金・制限への影響が大きくなる。
  なお3ターン目の回答には、入力時に紛れ込んだ制御文字（`[C`）がそのまま含まれていた。モデルは入力をそのまま受け取る。

### 発展：応答時間とトークン数の計測

`python -m app.ask --bench gemini-3.5-flash-lite gemini-3.5-flash -n 3` で、
モデル × 質問（一般的な用語 / 講座に固有のこと）ごとに、平均の応答時間・入力/出力トークン数・エラーを表にする。

| model | 質問 | 成功/試行 | 平均秒 | 平均入力tok | 平均出力tok | エラー |
|---|---|---|---|---|---|---|
| gemini-3.5-flash-lite | LoRAとは何ですか？ | 3/3 | 2.99 | 7 | 623 | - |
| gemini-3.5-flash-lite | AIE2026の講座の宿題にある | 3/3 | 2.93 | 21 | 451 | - |
| gemini-3.5-flash | LoRAとは何ですか？ | 3/3 | 15.97 | 7 | 721 | - |
| gemini-3.5-flash | AIE2026の講座の宿題にある | 2/3 | 15.44 | 21 | 628 | [503] |

- 考察：
  - `gemini-3.5-flash` は `flash-lite` より約5倍遅く（約16秒 対 約3秒）、出力トークンも少し多かった。
    出力量の差だけでは説明できないので、回答を始めるまでの処理時間が長いと考えられる（未確認）。
  - `gemini-3.5-flash` では、6回中1回が 503（モデルの混雑）で失敗した。429（レート制限）は今回は出なかった。
    今回の試行は計12回と少なく、無料枠の上限には達しなかった。
    ただし、遅いモデルは1回の拘束時間が長く、失敗したときの再実行も遅い。
    エージェント（第3回以降）のように1つの質問で複数回呼ぶ場合は、制限に早く達すると予想される。
  - 質問によって入力トークンは 7 から 21 に増えたが、応答時間への影響は、出力トークン数やモデルの違いの方が大きそうである。

### つまずいたこと

- 1回の質問が返らず止まる現象があった。Python が API に接続する段階（IPv6 の経路）で待ち続けていたのが原因で、
  同じ API に curl では届いていた。Python の接続先を IPv4 にすると解決した。
  無料枠の制限（429）ではなく、実行環境のネットワークの問題だった。
